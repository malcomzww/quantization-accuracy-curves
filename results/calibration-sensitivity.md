# How much does the calibration set change measured degradation?

Generated by `python scripts/generate_results.py`. Do not edit by hand.

**This file carries ratios, orderings and spreads only.** Absolute
perplexities live in `results/raw-measurements.md`, which is gitignored.
The reason is measured, not assumed: the same model on the same text
returns perplexity 17.761073017 on one thread and 17.761070597 on
twenty-four, because float reduction order depends on how BLAS splits
the GEMM. An absolute perplexity is a property of the runner's core
count, so committing one would fail the drift gate on any machine with
a different one. Relative thread jitter is 1.4e-7; every ratio below is
rounded to two decimals, leaving about five orders of magnitude of
slack.

## Setup

- Model: `HuggingFaceTB/SmolLM2-135M`, float32, CPU only
- Quantised layers: 210 linear layers (`lm_head` and embeddings excluded, as llama.cpp does by default)
- Quantiser: **real llama.cpp k-quant kernels** (`ggml_quantize_chunk` from the `ggml-base` library in the `llama-cpp-python` wheel), called through ctypes with a real imatrix
- Eval: perplexity over 7 non-overlapping 128-token windows of held-out encyclopedic prose (896 tokens)
- Calibration corpora: `encyclopedic` (Wikipedia-style expository prose), `code` (Python, SQL and JavaScript source), `chat` (Instruction-following dialogue turns)
- Deterministic: fixed vendored corpora, seed 20250825, no sampling
- Reproduce: `python scripts/generate_results.py`
- Raw artifact: `results/raw-measurements.md` (gitignored)

## 1. The headline: calibration choice moves degradation by more than a whole quantisation level

Same weights, same kernel, same eval text. The only thing that changes
between the columns is which corpus produced the importance matrix.
Values are perplexity degradation over the float32 baseline, as a
ratio expressed in percent.

| level | bits/weight | cal=encyclopedic | cal=code | cal=chat | spread (pp) | best |
|---|---|---|---|---|---|---|
| Q6_K | 6.56 | 2.15% | 2.59% | 2.39% | 0.44 | encyclopedic |
| Q5_K | 5.50 | 1.53% | 1.84% | 1.58% | 0.31 | encyclopedic |
| Q4_K | 4.50 | 6.27% | 7.46% | 7.47% | 1.19 | encyclopedic |
| Q3_K | 3.44 | 57.25% | 58.37% | 62.66% | 5.41 | encyclopedic |
| Q2_K | 2.62 | 181.36% | 194.23% | 219.91% | 38.56 | encyclopedic |

At **Q2_K** the choice of calibration corpus moves measured
degradation by **38.56 percentage points**. For scale, the
smallest step between adjacent rungs of the ladder 
(`Q6_K->Q5_K`) is **0.62 pp**.

So at the coarse end of the ladder, **the calibration corpus is worth
61.90x more than a whole step of quantisation level**. A paper
reporting "Q2_K costs X%" without naming its calibration set has
published a number with a larger uncontrolled term than the one it is
measuring.

## 2. The matched corpus wins at every level, and the ordering is stable

The eval text is encyclopedic prose. The `encyclopedic` calibration
corpus is therefore the *matched* one and `code` and `chat` are
mismatched. That asymmetry is deliberate and it is what makes the
direction predictable rather than incidental.

| level | best | middle | worst |
|---|---|---|---|
| Q6_K | encyclopedic | chat | code |
| Q5_K | encyclopedic | chat | code |
| Q4_K | encyclopedic | code | chat |
| Q3_K | encyclopedic | code | chat |
| Q2_K | encyclopedic | code | chat |

**Matched calibration wins at every level** -- asserted here, so this
file cannot be regenerated if it stops holding. Ordering is committed
rather than the perplexities because the gaps between corpora are about
six orders of magnitude larger than the thread jitter, which makes the
*rank* portable even though the values are not.

**The ladder is not monotone in bits/weight.** `Q5_K` (1.53%) beats `Q6_K` (2.15%).
The k-quant levels differ in block structure and super-block
scaling, not only in bit width, so fewer bits does not strictly
mean worse. Any claim of the form 'Qn costs X%' assumes an
ordering that the data here does not have.

## 3. Why: the corpora disagree about the MLP, not about attention

Cosine similarity between importance matrices, per layer kind, for the
most divergent corpus pair (`encyclopedic` vs `chat`). Cosine rather
than a distance because the quantiser only consults the vector's
*shape* -- scaling every importance by a constant cannot change which
feature is relatively more important.

These are bit-identical across thread counts: the statistic is a sum of
squares accumulated in float64, not a GEMM reduction. So unlike the
perplexities, they can be committed at full precision.

| layer kind | median cosine | min cosine |
|---|---|---|
| down_proj | 0.6672 | 0.1062 |
| gate_proj | 0.9883 | 0.9093 |
| k_proj | 0.9970 | 0.9907 |
| o_proj | 0.8647 | 0.5567 |
| q_proj | 0.9970 | 0.9907 |
| up_proj | 0.9883 | 0.9093 |
| v_proj | 0.9970 | 0.9907 |

**The disagreement is concentrated in `down_proj`** (median
0.6672) while the attention projections barely move
(all above 0.9970). That localises the mechanism: the
corpora largely agree about what attention attends to, and disagree
about which MLP intermediate features matter. `down_proj` is the one
layer whose *input* is that intermediate activation, so it is exactly
where a change of text distribution should show up.

This is asserted, and it is the part of the result that generalises
beyond these three corpora: it predicts that calibration choice will
matter most for quantisation schemes that treat the MLP down-projection
like any other tensor.

Pairwise, across all layers:

| corpus pair | median cosine | min cosine |
|---|---|---|
| chat vs code | 0.9130 | 0.0653 |
| chat vs encyclopedic | 0.9922 | 0.1062 |
| code vs encyclopedic | 0.9093 | 0.1069 |

## 4. Is the spread larger than the measurement noise?

Per-window losses, bootstrapped with `paired_delta_ci` from
`llm-eval-harness` (10,000 resamples, seed 0). The windows are
non-overlapping, so they are exchangeable and the pairing across
calibration corpora is exact -- the same windows are scored under
each. Reported as a **ratio of the delta to its own interval**,
since the delta itself is an absolute log-loss difference.

| level | corpora compared | delta / CI half-width | interval excludes 0 |
|---|---|---|---|
| Q6_K | encyclopedic vs code | 0.99 | no |
| Q5_K | encyclopedic vs code | 0.29 | no |
| Q4_K | encyclopedic vs chat | 0.43 | no |
| Q3_K | encyclopedic vs chat | 1.05 | yes |
| Q2_K | encyclopedic vs chat | 1.68 | yes |

**2 of 5 levels** show a calibration effect
whose bootstrap interval excludes zero. Where it does not, the
honest reading is that this eval set is too small to separate the
corpora at that level -- not that they are equivalent. With
7 windows the interval is wide, and that is
a stated limitation rather than a hidden one.

## 5. Per-tensor vs per-channel vs per-group

One real weight matrix, `model.layers.15.mlp.gate_proj` (1536, 576), under explicit affine quantisation.
The k-quants above are fixed at a 256-wide group, so they cannot sweep
granularity; this section uses the affine implementation in
`granularity.py`, which is pure numpy and therefore bit-identical
everywhere. Error is reported **relative to per-tensor at the same bit
width**, so no absolute MSE is committed.

`effective bits` counts one float16 scale plus one float16 zero point
per partition. Without it the comparison is meaningless: a finer
partition cannot lose on error, so error alone always favours the
finest option.

### 4-bit

| granularity | effective bits/weight | MSE relative to per-tensor |
|---|---|---|
| per-tensor | 4.000 | 1.0000 |
| per-channel | 4.056 | 0.0684 |
| per-group-192 | 4.167 | 0.0515 |
| per-group-96 | 4.333 | 0.0415 |
| per-group-64 | 4.500 | 0.0362 |
| per-group-32 | 5.000 | 0.0277 |

### 3-bit

| granularity | effective bits/weight | MSE relative to per-tensor |
|---|---|---|
| per-tensor | 3.000 | 1.0000 |
| per-channel | 3.056 | 0.1056 |
| per-group-192 | 3.167 | 0.0804 |
| per-group-96 | 3.333 | 0.0653 |
| per-group-64 | 3.500 | 0.0572 |
| per-group-32 | 4.000 | 0.0438 |

Per-channel costs **0.056** extra
bits per weight and removes **93.2%** of the
per-tensor error. It is the single best trade on the list and the
reason essentially every real format is at least per-channel.

The trade-off has a crossover worth naming. **per-group-32 at 3 bits**
costs 4.000 effective bits/weight; **per-channel at 4 bits**
costs 4.056 -- essentially the same budget.
At that budget the coarser-but-wider option wins: per-channel/4-bit
has **1.85x lower** error than
per-group-32/3-bit.

**Spending your bits on payload beats spending them on scales.**
That is the practical rule the section exists to establish, and it
is asserted below so this file cannot be regenerated if it flips.

## Limitations

- **Weight-only, dequantised to float32 for the forward pass.** The
  quantiser is the real llama.cpp kernel, but inference runs in float32
  on dequantised weights rather than through an integer GEMM. This
  measures the error the *quantiser* introduces, not the additional
  error a fused low-precision kernel would add. **No speed or memory
  claim is made anywhere in this repo**, because none was measured.
- **Activations and the KV cache are not quantised.** W8A8, FP8 and
  KV-cache quantisation are in the concept list this repo is anchored
  to and are *not* established here. Weight-only is the whole scope.
- **One model, 135M parameters.** Whether the calibration spread grows
  or shrinks with scale is exactly the question a reader will ask and
  this repo cannot answer it. A 135M model has less redundancy than a
  7B one, so the spread here is plausibly an upper bound -- but that is
  a hypothesis, not a result.
- **Small, vendored corpora.** The calibration and eval sets are
  hand-assembled paragraphs, not corpus-scale samples. Real imatrix
  builds use hundreds of thousands of tokens. Small corpora make the
  imatrices noisier, which if anything *inflates* the spread; the
  direction of that bias is stated rather than corrected for.
- **7 eval windows is a small sample.** The
  bootstrap intervals in section 4 are correspondingly wide, and at the
  finer quantisation levels the calibration effect is not separable
  from noise. The table says so rather than reporting the point
  estimate as if it were.
- **The eval text is encyclopedic, which privileges one corpus.** That
  makes the *direction* of the effect predictable by construction. What
  is measured is the magnitude, not the existence of an ordering.
- **Perplexity, not a task metric.** A 135M model is near chance on
  multiple-choice benchmarks, so a task eval would report the noise
  floor moving. Perplexity is dense enough to measure, but it is not
  the thing anyone deploys a model to do.
